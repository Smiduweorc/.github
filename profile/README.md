# Opinions

Our projects generally follow a few ideas:

- Solve one problem well. Problems can be grouped together and can contain multiple items, we do not do the unix philosphy. If there are too many sub-problems, make informed decisions to set boundaries. (A mission comes first, information helps you make a decision. If you lack information, make a decision to get information.)
- We force you to make safe/opinionated default choices.
- Keep dependencies to a minimum.
- Ship software we'd actually want to use ourselves.
- Have a little fun along the way.
- AI is fine, so long used reasonably. One human can't know everything. (No vibecoding, we want reviewed work or work done by competent humans)
- Our libraries are generally insects
- We are language agnostic in a sense that we use whatever language is best suited for us to solve a problem, we pick up a language to use when ever needed, we don't force a runtime to do something it should not be doing
- We are not anti-agile, we just don't really use it
- We do this for the love of the game and we do not care about "establishing a userbase or community", unless there is a good reason (e.g. getting usability opinions).
- DECIDE CORE COMMITMENTS EARLY, DETAILS MATTER, NEVER "just do an MVP and make changes later"! (Be it a spec or anything, this is important!)
- WE NEVER EVER advertise ourselves. We build for fun, not for a product, user base or anything like that. These libraries are for us to use and if you find it useful, good for you.
